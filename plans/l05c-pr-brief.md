### Goal
Add a PR Brief card to the Overview tab of the PR page. It shows a model-written summary, Risk areas and Review focus. It is generated by one synchronous `POST /pulls/:id/brief`, which makes exactly one logical `completeStructured` call over pre-computed facts and never over diff code. The brief is cached per PR in `pr_brief` (now workspace-scoped), with a stale flag when `head_sha` changes. Every file and line the model cites is checked against the PR's real files and hunks. Clicking a row opens that file on the Files changed tab, expanded, scrolled into view and highlighted.

### Recommendations
Non-blocking choices, each with its precedent:
1. **Units write no new test files.** This follows L05b plan decision 9 and the `run-plan` skill: a separate `test-writer` pass after wave 3 covers SPEC-09 "Tests" and SPEC-10 "Tests", including the S-16 grounding fixture. Units run the existing hermetic suites.
2. **`PrBrief.risks` stays the `Risks` object (`{ risks: Risk[] }`), and `history` becomes `PrHistory.default({ history: [] })`.** AC-2 says `Risk` and `Risks` stay unchanged. `PrHistory` is an object, not an array, so "default to `[]`" is read as an empty `PrHistory`. Clients read `brief.risks.risks`.
3. **`BriefExtraction.review_focus[].line` is `z.number().int()` without `.min(1)`, and there are no `.max()` length caps in the extraction schema.** A cap in the schema would turn an over-long answer into a schema failure and a paid retry. `groundBrief` truncates and snaps instead (AC-20, AC-22). The persisted `ReviewFocusItem` keeps `.min(1)`.
4. **`BriefMeta.provider` is `z.string()`**, so `contracts/brief.ts` keeps its zod-only imports. The service writes a `Provider` value.
5. **AC-10 dropped components map to `data_gaps` as follows:** `specs`→`specs`, hunk ranges beyond 3→`hunks_truncated`, findings→`findings`, files beyond 60→`files_truncated`. A caller-files drop is logged in `dropped_components` but adds no gap, because `blast` in `data_gaps` would falsely say that Blast was absent.
6. **Per-attempt `timeoutMs` = 45 000 ms** (`BRIEF_LLM_TIMEOUT_MS`). Neither Fastify (`app.ts:47`) nor `apiFetch` sets a request timeout. Three schema attempts at 45 s fit inside Node's default 300 s `requestTimeout`. The adapter default is 60 s (`adapters/llm/openai.ts:15`).
7. **The LLM failure maps to `ExternalServiceError('Brief generation failed')`** (502, `platform/errors.ts:31`). Zero files maps to `ValidationError('Pull request has no changed files')` (422). A missing PR maps to `NotFoundError('Pull request not found')`.
8. **The logger is injected as `new BriefService(container, app.log)`**, typed by a local `BriefLogger` interface. This is the `onboarding/routes.ts:21` precedent. `service.ts` must not import `fastify` types (`FASTIFY_ALLOWED_FROM`).
9. **A `brief/types.ts` is added** next to SPEC-09 S-1's file list, for the internal types. This follows the `onboarding/types.ts` precedent.
10. **`DiffTab` takes raw `targetFile` / `targetLine` strings and validates them itself** (U-21). The highlight is local state inside `DiffTab`/`diff-viewer`. SPEC-10 U-17's `onArrived` callback is dropped: nothing in the page needs it. The URL keeps the params for reload (AC-39), and unmounting on a tab change clears the highlight (U-19).

## 2. Architecture decisions
- **A new module `server/src/modules/brief/`** with `routes.ts`, `service.ts`, `repository.ts`, `helpers.ts`, `constants.ts`, `schemas.ts`, `prompt.ts` and `types.ts`. `BriefService` is constructed inline in `routes.ts` with no container getter. This is the `blast`/`onboarding` pattern, and it avoids the accepted-but-noisy `no-circular` baseline entry.
- **The Smart Diff classifier moves to `src/modules/_shared/smart-diff-classifier.ts`.** `_shared` is the only cross-module target `no-cross-module-imports` allows. The classifier depends only on `@devdigest/shared` types and its own literals, so it is safe there. `smart-diff/helpers.ts` re-exports `classifyFile`, so `smart-diff/service.ts` and `test/smart-diff-classify.test.ts` stay unchanged. A copy was rejected because the rules would drift (SPEC-08).
- **Cross-module reads use existing container repos only:**
  - `container.reviewRepo.getPull(ws, id)`, `.getRepo(repoId)`, `.getPrFiles(prId)`, `.reviewsForPull(prId)`
  - `container.intentRepo.getIntent(ws, prId)`
  - `container.repoIntel.getBlastRadius(repoId, paths)`
  - `container.agentsRepo.listEnabled(ws)` + `.listContextDocs(agentId, repoId)`, with no new agents method
  - `readProjectDocsAtRef(container.git, …)` from `platform/project-context/index.js`
  - `container.llm(provider)`
  - The `risk_brief` override is read from `settings` in `brief/repository.ts`, falling back to `FEATURE_MODELS.find(f => f.id === 'risk_brief')` (`contracts/platform.ts:60`, openai / gpt-4.1).
- **Grounding and facts assembly are pure functions in `brief/helpers.ts`.** The service orchestrates and holds the in-flight `Map<string, Promise<PrBriefResponse>>` keyed `${workspaceId}:${prId}` (S-7). The repository does one-statement upserts and reads.
- **The prompt is pure (`brief/prompt.ts`).** It uses `wrapUntrusted` from `@devdigest/reviewer-core`, the `intent/prompt.ts:9` precedent, with one block per fact group and one per spec doc.
- **Client:** three route-local components under `app/repos/[repoId]/pulls/[number]/_components/`; two hooks in `lib/hooks/reviews.ts`; `page.tsx` composes and owns `openFile` (`router.push`). Diff arrival lives in `DiffTab` plus the shared `components/diff-viewer/` (FileCard / GroupSection / DiffViewer gain optional props; default behavior is unchanged).
