# L03 — Intent Layer (server)

Package-local API contract. See the cross-package spec
`../../specs/L03-intent-layer.md` for the full feature scope, the provenance
contract, the no-diff-bodies rule and the degradation ladder; this file covers
the server-side contract and the reasoning behind it. Reference
implementations mirrored throughout: `modules/conventions` (cheap-model
feature with a provenance row, direct `settings`-table model lookup) and
`modules/reviews` (run-executor pre-work, `RunLogger` fan-out).

## Route table

New `intent` module —
`server/src/modules/intent/{routes,service,repository,prompt,sources,schemas,helpers,constants}.ts`,
registered with **one import + one entry** in `server/src/modules/index.ts`
(registration is STATIC, never autoload — `server/AGENTS.md:18-21`; the
registry comment at `index.ts:23` already lists "intent/smart-diff" as
expected).

| Method | Path | Body | Response | Notes |
|---|---|---|---|---|
| `GET` | `/pulls/:id/intent` | — | `200: PrIntentRecord \| null` | pure DB read — no clone I/O, no LLM, safe to poll |
| `POST` | `/pulls/:id/intent` | `z.preprocess((v) => v ?? {}, z.object({ force: z.boolean().default(false) }))` | `200: PrIntentRecord` | manual re-derive; `force` bypasses the `head_sha` cache |

Both use `IdParams` (`modules/_shared/schemas.ts:11`) and `getContext`
(`modules/_shared/context.ts:14`). `POST` is rate-limited
`{ max: 10, timeWindow: '1 minute' }`, matching `POST /pulls/:id/review`
(`modules/reviews/routes.ts:54`). Every query in `intent/repository.ts` is
scoped by `workspace_id`.

## Contracts (`vendor/shared/contracts/`)

⚠️ Barrel-collision gotcha (`server/INSIGHTS.md:147-167`):
`vendor/shared/index.ts` is 10 flat `export *` statements and a duplicate
identifier is silently dropped with no error anywhere. Grep the whole
`contracts/` directory for `IntentConfidence`, `IntentSourceKind`,
`IntentSourceStatus` and `IntentSource` before adding them.

`contracts/brief.ts` — `Intent` is **extended**, not replaced. The existing
three fields keep their names; in particular the assignment's "summary" maps
onto the existing `intent` field rather than a rename, because renaming the
column would trigger `drizzle-kit`'s interactive rename prompt, which needs a
real pty (`server/INSIGHTS.md:310-329`).

```ts
export const IntentConfidence = z.enum(['high', 'medium', 'low']);
export const IntentSourceKind = z.enum([
  'title', 'body', 'issue', 'issue_unkeyworded', 'spec', 'plan', 'files', 'hunks', 'commits',
]);
export const IntentSourceStatus = z.enum(['used', 'absent', 'unavailable']);
export const IntentSource = z.object({
  kind: IntentSourceKind,
  status: IntentSourceStatus,
  ref: z.string().nullish(),        // "#412", "specs/L03-intent-layer.md"
  chars: z.number().int().nullish(),
});
export const Intent = z.object({
  intent: z.string(),
  in_scope: z.array(z.string()),
  out_of_scope: z.array(z.string()),
  sources: z.array(IntentSource).default([]),
  confidence: IntentConfidence.default('low'),
  context_gaps: z.array(z.string()).default([]),
});
```

`contracts/review-api.ts` — `PrIntentRecord = Intent.extend({ pr_id })` gains

`contracts/findings.ts` — `Finding` gains `in_scope: z.boolean().nullish()`

`contracts/trace.ts` — `PromptAssembly` gains `intent` + `intent_tokens`,
copying the `skills` / `skills_tokens` precedent at `trace.ts:41-44`, so the

`contracts/platform.ts:53-58` — the `review_intent` entry's default changes
from `openai`/`gpt-4.1` to `openrouter`/`deepseek/deepseek-v4-flash`, matching
what the seeded agents already use (`server/INSIGHTS.md:193-207`) and what
`docs/agent-prompts/choosing-a-model.md:45-55` endorses ("cheap model for
advisory passes, strong model for the agent that blocks merge").
`client/src/lib/feature-models.ts:21-27` is a **hand-maintained mirror** and
is NOT covered by `check-vendor-sync.sh` — it must be edited separately.

## Schema (`db/schema/reviews.ts`)

One migration, `0014_*`, generated by `pnpm db:generate` — never hand-named
(root `AGENTS.md`, "Do not touch"). Drive the interactive rename-vs-create
prompt through a real pty; a piped `\n` does not work
(`server/INSIGHTS.md:310-329`). Every prompt answer here is "create" — no
column is a rename.

`pr_intent` is **extended** (purely additive; `pr_id`, `intent`, `in_scope`,
`out_of_scope` untouched):

```ts
workspaceId: uuid('workspace_id').notNull().references(() => workspaces.id, { onDelete: 'cascade' }),
sources:     jsonb('sources').$type<IntentSource[]>().notNull().default(sql`'[]'::jsonb`),
confidence:  text('confidence').notNull().default('low'),
contextGaps: jsonb('context_gaps').$type<string[]>().notNull().default(sql`'[]'::jsonb`),
headSha:     text('head_sha'),
provider:    text('provider'),
model:       text('model'),
tokensIn:    integer('tokens_in'),
tokensOut:   integer('tokens_out'),
costUsd:     doublePrecision('cost_usd'),
error:       text('error'),
generatedAt: timestamp('generated_at', { withTimezone: true }),
```

Plus `index('pr_intent_ws_idx').on(t.workspaceId)` — a new FK column that
every query filters on, and Postgres does not auto-index FK columns.

`workspace_id` is added **deliberately**. The table predates the rule and
scopes only transitively through `pr_id`, violating `server/AGENTS.md:24`
("every domain table carries `workspace_id`; every query scopes by it").
`notNull` on an existing table needs a backfill, so exactly one hand-written
statement is appended to the generated file **before it is ever applied**:

```sql
UPDATE pr_intent SET workspace_id = pr.workspace_id
FROM pull_requests pr WHERE pr.id = pr_intent.pr_id;
```

This is the only hand-written SQL in the plan, and it is legal precisely
because the file has not been applied yet — an *applied* migration is
immutable.

The provenance block mirrors `convention_scans`
(`db/schema/knowledge.ts:38-65`), the established shape for "a non-review LLM
feature's run record".

`findings` gains one column:

```ts
inScope: boolean('in_scope'),   // nullable: null = not classified (no intent)
```

Nullable on purpose — a review run with no intent leaves it `null`, which is
distinct from "classified as out of scope". `findingRowToDto`
(`modules/reviews/helpers.ts:18`) maps it explicitly.

## The derivation algorithm (`IntentService#ensureIntent`)

Called as shared pre-work from `ReviewRunExecutor#executeRuns`
(`modules/reviews/run-executor.ts:97-107`), immediately after the diff load
and before the per-agent loop, using the **fan-out** `RunLogger` so the step
appears in every target agent's Live Log — `platform/run-logger.ts:16` was
written for exactly this.

1. **Cache check** — if a `pr_intent` row exists with `head_sha` equal to the
   PR's current `head_sha` and no `error`, return it. **Zero** LLM calls.
   `force: true` skips this step.
2. **Source assembly** (`sources.ts#buildIntentSources`, pure, no LLM): PR
   title; PR body; `resolveIntentIssues(body)` → `container.github().getIssue()`
   per keyworded reference; in-repo plan/spec paths resolved from the existing
   clone plus GitHub blob URLs via the adapter; `pr_files.path` list;
   `@@ -a,b +c,d @@` header strings **reconstructed from `DiffHunk`'s
   numbers**; `pr_commits.message` first lines. Each produces one
   `IntentSource` with `status` `used` / `absent` / `unavailable`. A fetch
   failure is `unavailable` — **never** fabricated.
3. **Model resolution** — `repository.ts#getIntentModelOverride(workspaceId)`
   reads the shared `settings` table directly (exact copy of
   `modules/conventions/repository.ts:76-86`), falling back to
   `constants.ts#DEFAULT_INTENT_MODEL` (`openrouter` /
   `deepseek/deepseek-v4-flash`). It does **not** import
   `modules/settings/feature-models.ts` — see below.
4. **One `completeStructured` call** (`prompt.ts#buildIntentMessages` +
   `schemas.ts#IntentExtraction`), every source block individually wrapped via
   `wrapUntrusted` from `@devdigest/reviewer-core` with its own `source`
   label, as `reviewer-core/specs/prompt-and-grounding.md:25-27` requires for
   any new prompt input. Schema is passed as a Zod schema, never described in
   prose (`docs/agent-prompts/README.md:53-80`). Zod **3** →
   `toJsonSchema`, exactly as `ConventionExtraction` does; not Zod 4's
   `z.toJSONSchema`.
5. **Clamp** (`helpers.ts#clampConfidence`) the model's `confidence` against
   the deterministic `sources[]`, then attach `sources[]` (our value, never
   the model's).
6. **Persist** (`repository.ts#upsertIntent`) with the full provenance block
   and `generatedAt = now()`.
7. **On throw** — record `error` on the row (or leave no row), log at `warn`,
   and return `undefined`. The review run proceeds with no intent section and
   is **not** failed (`server/AGENTS.md:38-40`).

## Prompt-side gotchas

- The confidence rule is a **judgment**, so it belongs in the prompt, not in a
  `.describe()`: state that `confidence` must be `low` when only the title and
  file paths were available, and that any source listed as `unavailable` must
  be named in `context_gaps` rather than guessed at.
- Send `provider: { require_parameters: true }` on the OpenRouter call.
  Structured-output support is per *endpoint*, not per model, so without it
  OpenRouter can silently route to a provider that ignores `json_schema`. The
  repo does not do this today.

## Why the feature-model lookup isn't a container getter

Identical to L02's reasoning (`L02-conventions-extractor.api.md`, "Why the
feature-model lookup isn't a container getter"): a bare function import of
`settings/feature-models.ts` trips `no-cross-module-imports`, and wrapping it
as a `Container` method trips `no-circular` instead, because
`feature-models.ts` already `import type { Container }` and
`.dependency-cruiser.cjs` sets `tsPreCompilationDeps: true`
(`server/INSIGHTS.md:70-97`). Reading the shared `settings` **table** via the
Drizzle schema barrel is not a cross-module import of another module's code.

Conversely, `reviews` reaches intent through a new **`container.intentRepo`**
lazy getter on `platform/container.ts`, mirroring
`agentsRepo`/`reviewRepo`/`skillsRepo` (`container.ts:97-111`) — never a
sibling-module import (`server/INSIGHTS.md:99-123`). `IntentRepository` does
not import `Container`, so this getter is acyclic and safe.

## Response-schema discipline

Both routes declare an explicit `response:` schema (`PrIntentRecord`) and map
through `helpers.ts#toIntentDto`, which never returns a raw Drizzle row.
`generatedAt` (`Date`) becomes an ISO string before the handler returns. Per
`server/INSIGHTS.md:211-241`, `fastify-type-provider-zod` runs `safeParse` on
the in-memory object **before** `JSON.stringify`, so a raw `Date` 500s and an
undeclared key silently vanishes.

`GET` returning `null` is declared as `PrIntentRecord.nullable()` — a bare
`PrIntentRecord` schema would reject the null and 500.

## Body-less request handling

`POST /pulls/:id/intent` has an all-optional body. A body-less `app.inject()`
(and a real empty POST with no `Content-Type`) delivers `null`, not
`undefined`, and Zod's `.default()` only substitutes for `undefined`
(`server/INSIGHTS.md:243-266`). The body schema is therefore
`z.preprocess((v) => v ?? {}, …)`, matching `reviews/routes.ts:45`.

## Logging (`platform/run-logger.ts`)

No new logging mechanism — the existing triple sink (SSE Live Log →
`run_traces.log` → pino stdout). Emitted around the classifier call via
`runLog.step('Deriving PR intent', …, { kind: 'tool' })` so it renders amber
as external I/O:

```
Deriving PR intent…
  sources: title(used,42ch) body(absent) issue(#412,unavailable)
           files(9) hunks(14) commits(3)
  model: openrouter/deepseek/deepseek-v4-flash   est. ~780 tok in
Deriving PR intent done (1120ms)
  confidence: low · gaps: 1 · 812 in / 96 out · $0.0001
```

Deliberately **not** logged: no secrets (the classifier never sees one; keys
resolve through `SecretsProvider`), no source text (kinds, statuses and
character counts only), no diff content (hunk header *counts*, never header
text). Full prompt text stays in the run trace's prompt modal, the existing
deliberate place for it.

`tokensIn`/`tokensOut`/`costUsd` from `StructuredResult` are stored on
`pr_intent` **and** added to the run's totals, so the L01 cost badge tells the
truth about what the PR cost.

## Tests

- `test/intent-sources.test.ts` (hermetic) — no `^[+-]` diff line appears in
  the rendered messages and no fixture diff body text appears anywhere
  (the no-diff-bodies rule); title-only yields `confidence: 'low'`; a failed
  issue fetch yields `status: 'unavailable'` plus a `context_gaps` entry and
  never invented text; `clampConfidence` caps every documented case.
- `test/intent-issue-refs.test.ts` (hermetic) —
  `"see #4 for background. Closes #812"` resolves to **#812**, not #4;
  `owner/repo#123` and full issue URLs parse; multiple keyworded refs all
  return; a bare `#N` with no keyword is recorded as `issue_unkeyworded`.
- `test/intent-extract.it.test.ts` — `MockLLMProvider` + `seed()`; the
  `pr_intent` row persists with provenance; a re-run at the same `head_sha`
  makes **zero** LLM calls; `force: true` re-derives; workspace isolation.
- `test/intent-degraded.it.test.ts` — a throwing LLM leaves the review run
  `done`, not `failed`, and the prompt carries no intent section.

Every `.it.test.ts` calls `seed()` for its workspace row — a hand-inserted,
arbitrarily-named workspace is invisible to `LocalNoAuthProvider`'s exact-name
match and fails every request with "No default workspace found"
(`server/INSIGHTS.md:331-349`).
